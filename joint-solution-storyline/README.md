# 联合方案 & 二创视频故事线 Skill · 使用说明（README）

> 一句话定位：把**生态伙伴填的一份 QA 收集表**，变成**腾讯云×伙伴联合方案的「PPT 文字故事线」+「二创短视频叙事线」**两份同根同调的营销内容初稿。
>
> 🚨 **核心原则：demo ≠ default**。文档里出现的悦智 / 香港赛马会 / 信永中和都只是**测试过这个 skill 的样例**，不是默认对象。每次以你新给的 QA 表 + 选定案例为准。

---

## 一、什么时候用这个 Skill

**适用场景（命中任一即可用）：**
- 拿到一份**生态伙伴填写的「QA 收集表」**（里面有伙伴的联合解决方案、及其服务过的客户案例），需要把它加工成对外营销内容。
- 需要产出**联合方案 PPT 的逐页故事线 / 策划框架**（给设计师做 PPT 的文字底稿）。
- 需要产出**1.5 分钟社媒二创短视频的叙事线**（逐幕口播文案，用于视频号等轻传播、导流下载完整方案）。
- 需要基于「病-药-效」客户视角，把伙伴的功能罗列**翻译成打动客户老板的业务价值故事**。

**不适用场景：**
- 只是要做一个通用 PPT / 视频脚本，跟"腾讯云×生态伙伴联合方案"无关。
- 要直接产出成品 PPT 文件 / 成品视频——本 skill **只产文字故事线/叙事线**，成品制作交给设计/剪辑。

## 二、第一次使用：提示词该包含什么 + 需要什么配置 + AI 共创规则

### 2.1 建议的前置配置（开工前先设置好）

| 配置项 | 为什么 |
|---|---|
| ✅ **开启「内容创作专家」角色 / 团队** | 本 skill 输出的是市场营销文案，内容创作专家的笔力和营销语感明显更好。 |
| ✅ **善用 Google 侧边栏 Gemini 做检索** | 那里是**上下文一手的地方**：可以直接分享/引用你当前打开的网页标签页（伙伴官网、客户官网、腾讯云产品页），无需单独上传 context，检索出的内容效果也更好。做主动检索时优先用它。 |

> 🧰 **两个「可选增强」skill（装了更顺手，没装也能跑，不用特意去装）：**
> - **`anysearch`（前置检索环节可选）**：装了可以并行批量搜"伙伴+客户+腾讯云产品"三类官网、把整页转成干净 Markdown、做数据时效核对，比内置搜索更省事。**没装就用内置的网页搜索/抓取**，一样能查到，只是要逐个串行、内容稍杂。（注意：只查公开官网/公开行业数据；QA 表里未公开的伙伴敏感信息别丢给它。）
> - **`brainstorming`（搭策划案底座时，通常用不上）**：本 skill 的"缺信息就反问、关键节点先确认"这套提问纪律**已经内化在下方 2.3 的共创规则里，默认无需再装它**。只有当某个方案特别复杂、底座怎么搭都想不清时，才临时借它做纯发散讨论——且别让它把流程带到"写技术文档/代码"那步（那是它的用途，跟我们做营销文案不搭）。

### 2.2 首次提示词应包含的内容（越全，返工越少）

**必给：**
1. **伙伴 QA 收集表**（一手核心素材，`.xlsx`）——这是全部内容的事实来源。
2. **要产出哪个**：PPT 文字故事线 / 二创视频叙事线 / 两个都要。
3. **选哪个案例**：QA 表里通常有多个方案/客户案例，指定用哪一个（优先选**涉及 AI、出海**的案例）。没想好也行，AI 会帮你筛选并请你确认。

**最好也给（给了质量更高）：**
4. **推广的产品 + 目标受众**：这条视频/PPT 在推广什么方案、想打动谁（如"像该客户一样客群多元、咨询高频的 B 端服务型企业"）。
5. **有无可对外授权的客户案例**：决定"效果"部分能不能用真实客户名+数据，还是要脱敏抽象。
6. **参考范本**（可选但强烈建议）：好的联合方案 PPT / 已成片的二创视频文案。给了 AI 就能对齐笔力（这次赛马会案例就是靠信永中和范本校准的）。
7. **你心里已有的方向/偏好**：比如价值主线更偏"降本增效"还是"体验升级→收益增长"、Key Message 的雏形等。

### 2.3 基础 AI 共创规则（重要，决定协作顺不顺）

> 这个 skill 走的是 **brainstorming 式共创**，不是"一把梭一次性出终稿"。

1. **缺信息就反问，绝不瞎猜**：像 brainstorming skill 一样，遇到需要你拍板的地方（选哪个联合方案&哪个客户案例、价值主张走哪条线、Key Message 定稿），AI 会**停下来问你、给出建议+理由**，等你确认再往下写。
2. **关键节点先对齐，再产出**：以下三个必须**提前确认**——① 选定的案例；② 价值主张主线；③ Key Message。方向对了，内容才不白写。
3. **分轮迭代、反复反馈修改**：先出初稿 → 你批注 → AI 改 + 把可复用的改进**沉淀进 skill** → 再迭代。不追求一次到位。
4. **产出是"供与伙伴二次讨论的初稿"**，不是可直接对外发布的成品。AI 会主动标出"待伙伴确认/补充"的存疑点（推演的风险、目标值 vs 实测值、网络补充待核实处）。
5. **一手为准**：QA 表是伙伴亲填的一手资料，网络检索是二手补充；冲突时一律以 QA 表为准，网络内容像论文一样附信源附录。
6. **每次优化内容，同步优化 skill**：因为这是一个 demo，你在内容上的每条建议都要被抽象成**能泛化到任何伙伴/案例的通用规则**沉淀进 skill——否则就是"过度拟合到这一个案例"，白做 demo 了。

## 三、拿到 Context 后，AI 的工作 Step

### Step 1 · Context 阅读回执

拿到你给的所有材料（QA 表 / 图片 / PPT / 参考文案 / 链接）后，**先不动手**，而是给一份结构化「阅读回执」：
- ✅ **已完整读取并理解**：具体是哪些文件/图片/段落/链接。
- ⚠️ **部分查看 / 被截断**：看到哪、缺哪。
- ⛔ **跳过 / 无法查看**：工具打不开、格式不支持、链接失效等，说明原因。

回执之后**暂停**，等你确认或补料，不在同一轮直接输出结果。

### Step 2 · 前置主动检索（QA 是一手，但不够，必须补）

QA 表只是首轮一手素材，AI 会**主动上网检索**补充业务血肉与行业 know-how。**三类锚点（缺一不可）：**

| # | 检索什么 | 为了拿到什么 | 会用在哪 |
|---|---|---|---|
| 1️⃣ | **伙伴官网**（如伙伴的解决方案/客户案例页） | 伙伴的**公司主体能力**（团队规模、深耕行业、全生命周期交付能力）——**可泛化到任何案例的实力**，不是本案例的具体动作 | 「双方登场·能力与价值」拍讲"伙伴是谁" |
| 2️⃣ | **客户官网**（案例里那个客户） | 客户真实**业务场景**：体量、客群、咨询特点、痛点背景 | 开场"收窄到客户"、场景预设、共性提炼 |
| 3️⃣ | **方案涉及的腾讯云产品官网**（QA「涉及腾讯云产品」字段填了什么就逐个查） | 每个产品**到底是什么、核心能力、给这个场景带来什么价值** | 「方案架构·三步走」拍把腾讯云价值写实写专业 |

> 🔑 **mentor 强调**：上网搜的每一样东西，**都要体现在后面内容撰写的笔力里**，不是只作为"深入理解"。查到 ADP 是 Agentic RAG 检索引擎，就要在文案里写出"回答有据可查、可追溯到源文档"这种血肉，而不是泛泛一句"提供技术底座"。

### Step 3 · 先搭「策划案底座」，再分发成两种形式

这是本 skill 的**核心工作模型**——**两个产出物核心内容统一，同根同调**：

```
        ┌─────────────────────────────────────────┐
        │   核心故事线底座（策划案 · PPT 和视频共用）  │
        │  Key Message（一句北极星）                 │
        │  病：客户痛点（过翻译公式）                 │
        │  风险：痛点的代价                          │
        │  药：联合方案 + 腾讯云做什么 + 伙伴做什么     │
        │  效：客户价值/成效                         │
        └───────────────┬───────────┬───────────────┘
                        │           │
              分发形式 A ▼           ▼ 分发形式 B
     ┌──────────────────────┐  ┌──────────────────────────┐
     │  PPT 文字故事线        │  │  二创视频叙事线            │
     │  · 逐页要点+背后逻辑    │  │  · 逐幕口播，1.5 分钟       │
     │  · 每页一句客户视角结论  │  │  · 只抽主线、勾兴趣、导流    │
     │  · 输出为 Markdown      │  │  · 输出为 Excel（5 列表）   │
     └──────────────────────┘  └──────────────────────────┘
```

- **先定底座**：Key Message + 病药效，这是两个产出物的**同一个根**，保证 PPT 和视频"核心内容统一"。
- **再按形式分发**：同样的内核，因载体不同而有各自的结构——PPT 完整逐页展开、视频只抽主线。
- **各自的结构标准化**：见下方"二创视频叙事线结构"（这套是从香港赛马会 AI 智能客服案例梳理定型的）。

#### 📽️ 二创视频叙事线的标准结构（赛马会案例梳理定型，7 拍法）

| # | 视频结构 | 病药效角色 | 这一拍讲什么 |
|---|---|---|---|
| 1 | 黄金开场·数据钩子 | 病 | 权威第三方数据切入（趋势数据→痛点数据→高价值客群更狠的数据），事实自证紧迫性 |
| 2 | 场景收窄·点题 | 主张 | 用客户官网查到的具体数字收窄到本客户，抛出核心命题 |
| 3 | 痛点·几道考题 | 病 | 把 QA 的多条痛点**提炼成几个本质命题**（效率/精准/个性化/合规），每条翻译成客户能感知的坎 |
| 4 | 双方登场·能力与价值 | 药 | **先亮双方【主体实力】**：腾讯云是谁、伙伴是谁，各自提供什么价值（**不讲产品怎么用**） |
| 5 | 方案架构·三步走 | 药 | 学信永中和笔力，把**产品怎么落地**讲成有逻辑的分层架构（简单AI秒答→复杂AI辅助→底层合规） |
| 6 | 客户成效 | 效 | 用客户真实成效证明价值 |
| 7 | 结尾导流 | 尾 | 收口 Key Message（挂到 LTV/增值/复购）+ CTA 导流下载完整方案 |

> 🧱 **第 4 拍和第 5 拍的分层铁律（最易犯的重复错）**：第 4 拍讲**企业主体是谁、有多强**（腾讯云=全栈技术底座/混元+智能体平台+全球云；伙伴=团队规模/深耕行业/全生命周期交付）；第 5 拍才讲**产品怎么用**（ADP 的 RAG、Desk 的多轮、Workflow 编排）。产品能力一律下沉到第 5 拍，两拍不重复。
>
> PPT 文字故事线的逐页结构见 `references/ppt-storyline-spec.md`；二创视频叙事线的完整模板与生成技术经验见 `references/video-narrative-spec.md`。

### Step 4 · 脱敏检查 + 交付

过一遍脱敏清单（未授权客户名/金额/第三方企业名/未授权发布是否已隐去），在对话里交付（或你要求时写成文件：PPT→Markdown、视频→Excel），并**明确标注这是"供与伙伴二次讨论的初稿"**，列出需伙伴确认/补充的存疑点。

## 五、一句话记住这个 skill 的精髓

> **站在客户视角讲「病-药-效」**：先锁一句 Key Message，把伙伴的功能罗列**翻译**成客户老板关心的业务价值（落到钱/流失/LTV），主动上网把伙伴、客户、腾讯云产品**查实**再动笔，PPT 和视频**同根同调**，产出是**供二次讨论的初稿**——而且每一次优化都要**沉淀成能泛化的通用规则**，不困在某一个案例里。
