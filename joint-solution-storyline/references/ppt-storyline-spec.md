# PPT 故事线产出规格与页面模板

## ⚠️ 产出形态（用户 2026-07 明确要求，最高优先级）

PPT 故事线**不是"要点提纲"，而是"文字版 PPT"**——即**每页可直接落到画面上的成稿文案 + 清晰的信息层级标注**，交付对象是**做美化的设计师**。设计师靠"标题 / 副标题 / 小标题 / 描述 / 结论句"这些**层级词**读懂内容结构，才知道怎么排版设计。

**每页交付结构如下（用层级词标出信息层级）：**
```
### P{n}｜{页面定位，如"痛点页/能力页"}（一句话点明这页的逻辑角色，帮设计师和其他页区分）
- **标题**：这页 PPT 的大标题成稿（如"跨国财务管控：出海企业绕不开的"四道屏障""）
- **副标题/引导句**：（如有）标题下的一句引导
- **{要素}1 标题**：如"痛点1标题：数据不通 —— 信息孤岛林立"
- **{要素}1 描述**：如"海外业务地域分散、监管严格，财务系统各异、数据标准不一，导致财务数据割裂"
- ……（各要素同上，标题+描述成对）
- **总结句**：一句从客户价值/成效角度的收口。**判断规则：若"标题"本身已是客户价值角度的结论句，则无需再加总结句；若标题只是中性描述，则必须补一句客户视角总结句。**
- 【逻辑】：（给用户看的旁注，非落屏内容）为什么这么写、这页在故事线里的作用
```

**成稿文案的市场包装要求（关键）：**
> 伙伴填在 QA 表里的内容是"原始素材"，**必须从市场侧传播角度重新包装**，不能照抄：
> - **强化 Key Message 记忆**：与全案 Key Message 呼应。
> - **文案简洁有力**：标题短促有力（可用引号金句、对仗、数字），描述一两句说透。
> - **有行业 know-how 与专业深度**：体现对该行业/场景的理解，不空泛。
> - 层级词（标题/描述/总结句）是**给设计师的结构信号**，本身不一定落屏，但成稿文案要落屏。

## 旧版要点式（仅当用户明确说"只要要点提纲"时用）

每页交付两部分：
- **【要点】**：这一页该放哪些内容（要点化，不写满版正文）
- **【逻辑】**：为什么这么放（背后的策划意图）
- **【客户视角结论句】**：一句放在标题或页面结论位、讲"这对客户意味着什么价值/成效"

## 四条硬规则（重申）

1. 框架 = 每页要点 + 背后逻辑。
2. 每页一句客户视角结论（价值/成效，不是技术动作）。
3. 一页一主题，不拆散注水。
4. 每页字数克制，杜绝满屏技术堆砌。

## 病药效撰写方法论（与视频共用同一套，见 SKILL.md 约束六）

PPT 与视频**共用底层逻辑**，避免两份规格打架。撰写各页时同样遵循：

- **KM 落结果价值**（六-B）：封面/收尾的 Key Message 必须落到"客户想要的结果"，不停在"听懂/识别/连接"这类过程中间态。
- **痛点翻译公式**（六-C）：痛点页每条走 `功能语 → 客户后果 → business 损失`，落到会让企业痛的利益点；QA 里的供应商功能语（"重复咨询量大""知识散落各处"）**不可照抄上屏**。
- **场景预设 + 共性提炼**（六-E）：行业趋势/背景页不要只讲一家客户，先检索客户业务体系，再提炼同类企业共性，让"病"覆盖一类目标企业。
- **能力分层 + 双方价值**（六-F）：方案页把散乱能力点重组成分层递进架构；单独一页（或一块）讲清"腾讯云做底座 × 伙伴做定制交付"的各自具体价值（1+1>2 落到实处，不空喊"强强联合"）。
- **信源附录**：若某页数据/行业事实来自网络检索，在故事线末尾附"信源附录"，逐条标 `[序号] 内容 —— 标题 —— URL`，页内相应处 `[序号]` 呼应。

## 推荐页面骨架（病-药-效展开）

按方案复杂度可增减，核心是"病→药→效"三段清晰、每段不超必要页数。

### 开篇（点题）
- **封面页**：方案名 + 一句 Key Message（客户视角的核心承诺）
- **目录页**：四段式（趋势/背景 → 痛点 → 方案 → 价值），让观众预知故事线

### 病（客户痛点，1-2页）
- **行业趋势/背景页**：为什么现在客户会遇到这个问题（宏观趋势切入，建立共鸣）
  - 结论句示例："出海已从'要不要'变成'怎么做好'——而XX成了绕不开的坎"
- **痛点页**：客户的核心痛点（3-4条，逐条客户视角）+ 每条痛点带来的风险/代价
  - 一页讲清"病+风险"，不要拆开
  - 结论句示例："这些痛点不解决，客户面临的是XX风险（合规罚款/决策滞后/信任流失）"

### 药（联合方案，2-4页）
- **方案总览页**：方案是什么、整体架构（如三层架构一图流）
  - 结论句：从客户视角讲"这套方案帮客户实现了什么"
- **能力分解页**（按方案模块，每模块可一页或合并）：腾讯云能力 + 伙伴能力如何互补
  - ⚠️ 讲能力时点技术，但每页结论句要落到客户价值
  - 1+1>2 协同在这里体现，但**点到即止**，不喧宾夺主
- **差异化价值页**：对标竞品，只有腾讯云×伙伴能给的价值（"你有我没有"）
  - 结论句：客户为什么非选这套不可

### 效（客户价值/成效，1-2页）
- **价值成效页**：
  - 有授权案例 → 真实客户名 + 量化成效（如"2小时GMV近400万"）
  - 无授权 → 抽象成"这类客户普遍能得到的业务价值"（如"采集提效90%+、报表数周→分钟级"）
  - ⚠️ 全部翻译成客户业务语言，不是技术功能
  - 结论句 = 收口到 Key Message

### 收尾（升华）
- **升华页**：收口 Key Message + 生态愿景（如腾讯云出海生态启航计划框架，视场景而定）
- **联系/引导页**：如何进一步了解/合作

## 实操范例：客服 / AI Agent 类联合方案（11 页序，仅示例非默认）

> 🚨 此范例基于一次 demo 测试（某 AI 客服方案），**页序可复用，但具体伙伴/客户/KM 都是示例，非默认**。现有骨架偏财务/直播，此范例补充"AI 客服/智能体"类方案的落地页序：

| P | 页面 | 病药效 | 要点 |
|---|---|---|---|
| P1 | 封面 | — | 方案名 + Key Message |
| P2 | 目录 | — | 四段式预告 |
| P3 | 行业趋势 | 病·背景 | 为什么现在客户非上 AI 客服不可（场景共性提炼，覆盖一类企业） |
| P4 | 痛点页(四道坎) | 病+风险 | 3-4 条客户痛点并列，每条走翻译公式落到利益损失 |
| P5 | 方案总览 | 药 | 分层架构一图流(简单问题层/复杂辅助层/合规层) |
| P6 | 核心能力 | 药 | 按分层讲，每条落客户价值 |
| P7 | 1+1>2 协同 | 药 | 腾讯云底座×伙伴全生命周期各自价值，点到即止 |
| P8 | 差异化价值 | 药 | 只有这套组合能给的价值 |
| P9 | 客户成效 | 效 | 授权→真名+数据(注意目标值vs实测值) |
| P10 | 行业复制价值 | 效 | 从单案例升维到行业可复制 |
| P11 | 升华收尾 | — | 收口 Key Message + 生态愿景 |

Key Message 撰写提示（呼应约束六-B）：AI 客服类方案的 KM **不要停在"听懂/识别"这类过程中间态**，要落到客户想要的**结果**——问题被精准解决、体验提升、把咨询转化为留客/长期经营价值。（例如"不只省人力，更把每一次咨询变成一次留客机会"——示例，非默认。）

**总结句规则的实操落点**（呼应产出形态章节）：
- 痛点页标题若是"四道坎"这类中性描述 → **需补**客户视角总结句（如"每一道坎，都是服务体验与客户的流失缺口"）。
- 成效页标题若已写成价值结论句 → **无需**再加总结句。

## 反面案例警示

以下写法要避免（源自真实反面页）：

1. **满屏技术堆砌**：一页塞入"TCE/TDSQL/TBDS/TOS/TCS/TI + 每个的3-4条参数"——信息密度过高，观众读不完。
   - 正解：技术底座一页流图示，参数进备注，页面只留"客户能得到的可靠性/性价比"结论。
2. **纯技术语言当价值**：把"GAP动态路由/WAF/零信任/A-B-C三表/13期调整"当卖点。
   - 正解：翻译成"数据秒级归集、全链路安全、报表一键生成"等客户听得懂的话。
3. **一个内容拆多页注水**：把"数据安全"拆成加密页、权限页、审计页三页。
   - 正解：合并成"全链路数据安全"一页，三点并列。

## 交付格式（在对话里）

```
## 【核心故事线底座】
- Key Message：……
- 病：…… / 风险：……
- 药：腾讯云做…… + 伙伴做…… + 差异化……
- 效：……（注明有授权/脱敏模式）

## 【PPT 逐页框架】
### P1 封面
- 【要点】……
- 【逻辑】……
- 【客户视角结论句】……
### P2 目录
……（逐页）
```
