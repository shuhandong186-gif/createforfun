# 二创短视频叙事线产出规格与模板

基于联合方案 PPT，产出 ~1.5分钟社媒短视频的叙事线。**同一套病-药-效底座、同一个 Key Message**，但只抽主线、勾兴趣、导流下载完整方案。

> 🚨 **demo≠default**：本文出现的悦智 / 香港赛马会 / 信永中和等均为**脱敏举例**，不是默认对象。每次以用户新给的 QA + 选定 case 为准。

## ⭐ 撰写前必做的 6 步方法论（会议复盘沉淀，最重要）

这 6 步是二创视频叙事线**质量过关的关键**，落笔前逐一走一遍（详见 SKILL.md 约束六）：

1. **锁定推广产品 + 目标受众**：想清楚"这条视频在推广什么方案、要打动谁"。受众是"像该客户一样有同类需求的一类 B 端企业"，不是只讲一家客户。
2. **价值主张定线**（AI 判断+给理由→请用户确认，不锁二选一）：核心叙事走"降本增效"/"体验升级→收益增长"/两者兼有/全新主张？读出伙伴填表背后真正想强调的，并往"帮客户赚钱/留客/长期价值"深挖一层——不停在"省人力"。
3. **痛点翻译公式**（功能语→客户后果→business损失）：QA 填的"重复咨询量大/知识散落各处/多语言"是供应商功能语，**禁止直接上屏**；翻译成"响应慢、排队久、等待超时就流失、口碑受损"这类会让企业痛的利益点。**落点排序：收益/客户流失（企业最 care）> 品牌声誉/形象**；**禁写"员工负担重/减负/人工接得住吗"这类企业不 care 的内部视角**，要翻到"由此导致客户体验差/流失"。
4. **开场数据钩子**：开场优先用**具体、精准、带数字**的权威第三方调研数据（主动上网查，附信源；查不到标"待补权威数据源"，不编造），对标信永中和"488 亿合规支出"式开场。🚨 **严禁为贴场景把数据泛化成"正确的废话"**（写太泛虽无错但毫无吸引力、不专业）。推荐逻辑链：**趋势数据 → 过渡句(为什么投,落到钱/收益) → 痛点数据(等待→流失→收益损失) → 收窄到具体客户**。
5. **场景预设 + 共性提炼**（mentor 会议"可复用公式"）：`选价值词 → 上网查该客户背后的服务体系（客群/体量/咨询特点）→ 提炼成同类企业 2-3 条共性特征 → 给共性配权威数据钩子 → 落到结果(流失→丢收益)`。先检索客户业务体系预设真实场景 → 提炼同类企业共性，让引子覆盖一类企业。
6. **能力重组分层 + 双方价值·分主体与产品两层**（学信永中和"三步走"具体笔力，别写泛）：
   - 🧱 **【分层铁律】"双方能力"拍讲【企业主体实力】，"方案架构"拍才讲【产品落地】，两拍不重复**：双方能力拍讲腾讯云是谁（全栈技术底座/混元+智能体平台+全球云）、伙伴是谁（**从官网提炼可泛化到任何案例的公司实力**：团队规模/深耕行业/全生命周期交付），不点产品名怎么用（学信永中和"已在全球23国设112办公室"纯主体白描）；产品能力（ADP的RAG/Desk多轮/Workflow）下沉到方案架构拍。
   - 🔗 过渡句**禁"强强联合"万金油**，改用"提供从 X 到 Y 的一站式落地解决方案"，直接说清 1+1>2 具体价值。
   - 把散乱能力点重组成有递进逻辑的分层架构（如 简单问题AI秒答 → 复杂问题AI辅助人力 → 底层合规安全），每步"一句能力+一句解决什么"、善用 QA 原文具体词（如"三轮上下文""可追溯源文档""Workflow 编排"）；**腾讯云产品价值必须先查产品官网写实**（QA「涉及腾讯云产品」填了什么就查什么），不泛泛说"提供技术底座"。
7. **结尾收口 Key Message（差异化融进 KM，不单开"升华"拍）**：结尾**不空喊"这套能力不只属于本客户/适用更多场景"**（大家都知道，无信息量）。**"差异化升华"拍通常删掉**（易与成效/架构重复）——把本方案独有价值直接融进结尾 CTA 的 Key Message 收口，一句点睛；KM 落点挂到与钱相关的终局价值（LTV/复购/增值），别停在"读懂客户"这类感知词。
8. **旁白文风克制、像"陈述事实"不像"上课"**（约束六-G，最易翻车）：写旁白 ≠ 把"讲逻辑的口水话"搬上屏。①🚫 禁自问自答教学腔（"为什么企业愿意投？答案是…"是讲给同事听的逻辑，要消化后用营销语言重写）；②🚫 禁领导/说教口吻（"别忘了…""代价远超想象"）；③🚫 反问克制到几乎不用（范本零反问，优先陈述句+事实因果）；④🚫 禁口水词/形容词堆砌凑气势（"等得越久走得越快""如潮水般涌来"——每句要带信息量）；⑤🖋️ 比喻/金句必须贴本方案场景，不照抄范本（信永中和用"账本"是因它做财务，AI 客服场景不能套"账"；学的是笔法不是比喻词）；⑥📊 数据用最具冲击力的具体形态（"仅占 3% 的 VIP 贡献 40% 收入"＞"少数客户贡献四成"），行业规律用具体数字陈述即可、不越界套到本客户头上。
9. **KM 情绪基调贯穿全片、过渡句完成攻守转换（改 KM 后必做一致性巡检）**：KM 基调分**防守/止损**（防流失）与**进攻/增长**（提忠诚/复购/二次增长/LTV）两类。⚠️ 常见病：KM 升级成"增长"了，但开场/收窄/过渡句还一路喊"流失/去留"，结尾"增长"显得突兀无铺垫。✅ 正确情绪曲线 = **开场用流失制造紧迫（防守）→ 中段过渡句完成"防流失→促增长"攻守转换（枢纽）→ 结尾落进攻基调**；收窄拍/过渡拍就要埋"长期经营·持续创造价值"的增长种子。🔑 **痛点→方案的过渡句是攻守转换枢纽**，别只写"为了优化客户体验"（太平），要顺势抬到 KM 终局。📋 改 KM 后逐拍巡检：开场落点词/收窄收口句/过渡句/成效价值词/结尾 CTA，都要朝 KM 基调收敛，打架的就改。

## ⚠️ 产出形态

二创视频叙事线**产出为 Excel 表格**，表头固定 5 列：

| 视频结构 | 关键目标 | 文案结构 | 文案内容（旁白） | 预计时长 |
|---|---|---|---|---|

- **视频结构**：黄金开场 / 价值锚点 / 场景演绎 / 关键回顾 等叙事段落名。
- **关键目标**：这一段要达成什么（如"一句话总结业务痛点""方案总述及分层价值"）。
- **文案结构**：这一段的内容类型（如"数据钩子""痛点翻译""双方能力及价值""分层架构""价值总结"）。
- **文案内容（旁白）**：可直接配音的成稿口播文案。
- **预计时长**：如 5s / 15s / 25s，全片合计 ~1.5 分钟（约 80-96 秒，**不要做成 5 分钟的重版**）。

> 表格结构参考行业内既有的"5 列视频脚本表"，但**文案密度要对齐 1.5 分钟的口播范例**（约 300-360 字口播），不要照抄 5 分钟版的冗长文案。
> 若产出物含网络检索来的数据/事实，**在 Excel 末尾追加"信源附录"行**（或单列一个 References sheet），逐条 `[序号] 引用内容 —— 来源标题 —— URL`，正文旁白相应处用 `[序号]` 呼应。

### 结构公式（会议验证升级版，优先用这套）

对齐信永中和范例已验证的骨架，把散乱内容排成有逻辑的叙事流：

```
数据钩子 → 收窄到具体客户场景 → 痛点白描（客户可感知的坎） → 双方【主体】能力及各自价值 → 方案分层架构（三步走·产品落地） → 客户成效 → 点题 + CTA
```

> ⚠️ **顺序铁律（会议纠正）**：痛点讲完之后，**先介绍"腾讯云×伙伴各自的能力与价值"，再讲方案架构，最后才是客户成效**——这正是信永中和范本的顺序（"信永中和已在全球23国…腾讯云3200余节点…联合推出方案 → 方案分三步走 → 一个平台看清全貌"）。不要把"双方价值"塞进方案架构拍里一笔带过，它值得独立一拍先亮相。
>
> 🧱 **分层铁律（约束六-F，最易犯的重复错）**：
> - **「双方能力」拍讲【企业主体实力】**——腾讯云是谁（全栈技术底座/混元+智能体平台+全球云）、伙伴是谁（团队规模/深耕行业/全生命周期交付，从**官网提炼可泛化到任何案例的公司实力**），**不点产品名怎么用**。学信永中和"已在全球23国设112办公室"那种纯主体白描。
> - **「方案架构」拍才讲【产品怎么落地】**——ADP 的 RAG、Desk 的多轮、Workflow 编排等具体产品能力如何分层。
> - 🚫 别把产品能力提前写进"双方能力"拍导致和"方案架构"拍重复；别把本案例的具体交付动作（搭这个知识库/定制这个UI）当成伙伴公司主体能力（那太限于单案例）。
> - 🔗 双方能力拍的**过渡句禁用"强强联合"**这类万金油，改用"提供从 X 到 Y 的一站式落地解决方案"，直接点出 1+1>2 具体带来什么价值。
>
> ✂️ **"差异化升华"拍通常删掉**：实测它极易与"客户成效""方案架构"重复。把差异化价值直接融进结尾 CTA 的 Key Message 收口即可，无需单开一拍。

### 痛点白描：提炼成"几个本质命题"，不要口水化罗列

QA 的多条痛点（如重复咨询/知识分散/双客群三语/敏感合规）**不要逐条口水化白描**（"客户等得越久走得越快"这类不专业），而是**提炼成几个并列的本质命题**，每条一个关键词打头：
- 效率——能否快速响应，而不是排队流失；
- 精准——能否命中真需求、答案可追溯（快而不准同样流失）；
- 个性化——双客群/多语言能否差异化服务；
- 合规——敏感内容能否实时拦截、守住品牌声誉。
> 落点：前几条关乎**客户体验与留存**（防流失/收益），最后一条关乎**品牌安全**（声誉）。用"第一/第二…"或关键词打头的并列结构，干净、有信息量，避免形容词堆砌。

### 推荐拍数编排：7 拍法（删差异化升华，优先用这套）

| # | 视频结构 | 病药效 | 时长 |
|---|---|---|---|
| 1 | 黄金开场·数据钩子 | 病·权威数据（趋势+痛点数据+VIP 15s/3%40%） | ~12s |
| 2 | 场景收窄·点题 | 主张·收窄到具体客户（用官网直数） | ~8s |
| 3 | 痛点·几道考题 | 病·提炼成本质命题（效率/精准/个性化/合规） | ~14s |
| 4 | 双方登场·**主体**能力与价值 | 药·腾讯云×伙伴各自**主体实力**（先于架构，不讲产品） | ~16s |
| 5 | 方案架构·三步走 | 药·分层架构+**产品落地**（学信永中和笔力） | ~16s |
| 6 | 客户成效 | 效·客户真实成效 | ~10s |
| 7 | 结尾导流 | 尾·点题+CTA（KM 收口到 LTV/增值/复购） | ~8s |

> 「差异化升华」拍已按约束六-F 删除（易与成效/架构重复）；如某次方案确有强独特卖点、且不与前面重复，可临时加回一拍一句点睛，但默认不设。
> 备选 9 拍法（开场拆两拍）见下，但**顺序都须遵循"痛点→双方主体能力→方案架构→成效"铁律**。

1.5 分钟视频用 **9 个叙事拍**编排比笼统 5 段更利于配音/分镜，实测合计约 90-96 秒：

| # | 视频结构 | 病药效 | 时长 |
|---|---|---|---|
| 1 | 黄金开场·数据钩子 | 病·权威数据 | ~10s |
| 2 | 黄金开场·痛点翻译 | 病·客户可感知的坎 | ~10s |
| 3 | 主张点题 | 主张(KM) | ~8s |
| 4 | 方案登场·双方价值 | 药·腾讯云×伙伴各自价值 | ~14s |
| 5 | 分层架构① | 药·简单问题层 | ~12s |
| 6 | 分层架构② | 药·复杂辅助层(+合规层) | ~12s |
| 7 | 成效收束 | 效·客户成效 | ~12s |
| 8 | 价值升华 | 效·行业延展/长期价值 | ~8s |
| 9 | 结尾导流 | 尾·点题+CTA | ~8s |

要点：
- **开场拆两拍**（先用权威数据制造焦虑，再把痛点翻译成客户可感知的坎），比一拍开场更抓人。
- **能力段按分层架构讲**（六-F），不是平铺罗列几个独立能力点；并在方案登场拍点明"腾讯云做什么、伙伴做什么"。
- **"文案结构"列用"病·/主张·/药·/效·/尾·"前缀标注**，让读者一眼看清每拍在病药效里的角色。
- **"预计时长"列写成"起止时间码 + 约 Xs"**（如 `0:28–0:42\n约 14 秒`），方便剪辑对齐。
- 全片合计约 90-96 秒最佳；**生成后务必回读、累加各拍时长校验 ≈1.5 分钟**，超了就压缩文案。
- **语速硬校验（易踩坑）**：生成后必须回读，计算「旁白总字数 ÷ 总秒数 = 字/秒」。中文商业宣传旁白合理区间 **4.5–6 字/秒**（新闻联播约 5 字/秒）。若 >6 说明文案塞太满、念不完，必须精简（1.5 分钟片总字数约 **450–550 字**）。实测教训：曾写到 742 字/98 秒（7.6 字/秒，实际要 3 分钟才念完），压缩两轮才达标。

### xlsx 生成技术经验（openpyxl，避坑）

- 首行合并做**标题行**（蓝底白字），第二行合并做 **Key Message 备注行**（浅蓝底、强调色），第三行才是 5 列表头。
- 表尾加一行**"合计时长"**（前 4 列合并右对齐 + 第 5 列填合计秒数）。
- **旁白列用强调色**（如红字 C00000）与其他列区分，视觉突出核心口播。
- ⚠️ **中文引号坑（踩过）**：Python 脚本里凡是**字符串内容**含引号（如"被『听懂』"），一律用**中文全角引号「」或『』**，切勿用英文双引号——否则与外层字符串定界双引号冲突，报 `SyntaxError: invalid syntax`。或整个字符串改用单引号包裹。
- ⚠️ 若参考的 xlsx 用 openpyxl 打不开（报 `Fill() takes no arguments` 等样式兼容错），改用**原始 XML 解析**（zipfile + ElementTree 读 sharedStrings + worksheet）只取表格结构。
- 列宽建议：视频结构 16 / 关键目标 26 / 文案结构 14 / 旁白 52 / 时长 14。
- **信源附录（凡引用网络数据必附，像论文附录）**：表尾另起「📎 信源附录」小节，逐条列 `引用数据/事实 → 用于哪拍 → 来源 → 可靠性&备注`。可靠性要如实标：一手（官网/机构原文）✅、二手转述 ⚠️（注明"待核实/建议二次讨论替换"）；并注明"冲突时以伙伴 QA 表一手资料为准"。目标值（如"RAG 对标 90%"）若非实测要标出、慎用。

## 五条硬规则（重申）

1. ~1.5分钟；口播字数按**语速 4.5–6 字/秒**倒推，约 **450–550 字**（旧口径"300-360 字"偏保守，实测念得太快、留白过多）。
2. 病-药-效同一逻辑，但**只抽主线，不面面俱到**。
3. **弱化"两家各做了什么"**，重心放客户价值。
4. 头尾点 Key Message，结尾导流"下载完整方案"。
5. 目的：视频号等社媒传播，勾兴趣、低理解成本。

## 叙事结构模板（源自信永中和范例，抽象化）

范例总时长 0:00-1:19，可拆成 5 个叙事段：

### 段① 病·钩子（0:00-0:15）
- **用一个权威第三方调研数据/事实开场**（约束六-D），制造"这事跟我有关"的紧迫感——**不要用主观场景白描**（如"重复的问题、爆满的咨询"这类无数据锚的白描说服力弱）。
  - 范例（示例，非默认）："2024年，中国出海企业合规支出达488亿元，同比增长10%。"
- **点出客户痛点的本质**：走痛点翻译公式（约束六-C），把供应商功能语翻成客户可感知的损失。
  - ✅ 翻译后示例："查得慢、答不准、等得久——客户的耐心，往往撑不过几秒钟。"
  - ❌ 反例（禁用功能语白描）："知识散落各处、重复咨询量大。"

### 段② 转场·实力铺垫（0:15-0:35）
- **用主体实力白描亮出双方，不用"强强联合"这类空泛词**（约束六-F 分层铁律）：讲清腾讯云是谁（主体实力）、伙伴是谁（从官网提炼的公司主体能力），过渡句用"提供从 X 到 Y 的一站式落地方案"直接点 1+1>2 价值。
  - 范例："信永中和已在全球23国设112个办公室。腾讯云3200余加速节点、60余可用区。联合推出……方案。"（纯主体实力白描，不提产品怎么用）
- 顺带**预告结尾**"完整方案获取路径见片尾"。

### 段③ 药·方案主线（0:35-1:00）
- **分3步讲方案怎么解决**（学信永中和"三步走"笔力：每步一句能力 + 一句解决什么，具体、有画面、善用 QA 原文具体词，别写泛）。
  - 范例（示例，非默认）："第一步，全球基础设施一键覆盖；第二步，多准则智能转换；第三步，AI票据识别与报表合并，准确率超99.9%。一个平台，看清所有海外子公司财务全貌。"
- **补一句"双方各自价值"**（约束六-F）：谁做技术底座（腾讯云的具体产品能力，须查官网写实）、谁做定制交付（伙伴的具体角色），点明"客户无需多方拼凑"。

### 段④ 效·升华（1:00-1:15）
- **一句客户价值成效** + **点 Key Message**。
  - 范例："一个平台，看清所有海外子公司财务全貌。合规不再是成本项，而是全球化能力的一部分。"
- 🏁 **升华要落到"本方案差异化价值"，不空喊"适用更多场景"**（约束六-F）：再次强调"为什么企业需要我们这个方案"——本方案独有的、竞品给不了的价值点，而不是"这能力还能用在别处"这类常识空话。

### 段⑤ 导流（1:15-end）
- **明确 CTA**：去哪、做什么、下载什么。
  - 范例："关注腾讯云市场精选，主页选择出海专区，下载完整解决方案。"

## "效"的处理（同 PPT 约束）

- 有授权案例 → 可点真实客户成效数据。
- 无授权 → 用方案层面的普适成效（如"准确率超99.9%"这类方案能力数据），**不点未授权客户名**。
- 范例即无授权模式：全程未出现"金川"，用方案能力数据（99.9%）+ 广义价值收口。

## 与 PPT 的差异速记

| | PPT 故事线 | 二创视频叙事线 |
|---|---|---|
| 长度 | 完整逐页 | ~1.5分钟 |
| 详略 | 病药效充分展开 | 只抽主线 |
| 1+1>2 | 可含协同闭环拆解 | 主体实力一句白描+"从X到Y一站式"过渡句（禁"强强联合"空词） |
| 目的 | 完整说服/落地依据 | 勾兴趣、导流下载 |
| 结尾 | 升华+合作引导 | 明确 CTA 下载 |
